pandas CI on Namespace: cache diagnosis

The runner migration restored its cache but rebuilt most native code. I traced the misses to one locale variable, removed the mismatch, and reran the same pandas build and 4,045 groupby tests.

4 vCPUs, 16 GB RAM, Linux x86_64. Same source edit, dependency lockfile, build command, and tests.

Result after the fix

Namespace returned passing checks in 80s, compared with 225s unchanged and 126s on GitHub. All three restored the same original cache archive and passed the same 4,045 tests.

Namespace set LC_ALL=C.UTF-8; GitHub left it unset. Both set LANG=C.UTF-8. Ccache hashes those environment variables, so the extra LC_ALL field changed the key despite the same effective locale. Removing it restored 59/59 compiler-cache hits, up from 3/59.

The Namespace build took 24.38s after the fix versus 157.18s in the unchanged control. This was an environment mismatch, not evidence of slow Namespace hardware.

Suggestion for Namespace
Document this ccache migration case, including LANG and LC_ALL. For the Ubuntu runner used here, check whether the default locale environment can match GitHub’s. A cache restore can succeed while compiler-cache reuse fails.
The fix keeps ccache’s validation enabled. It removes a redundant locale override rather than ignoring cache-input differences.


Verification and evidence
The ccache debug inputs for a representative object matched after removing the extra LC_ALL entry. Compiler, Python/NumPy header, and selected system-header manifests also matched. Ccache documents hashing locale variables because they affect compiler warning messages.
A separate control run restored the same immutable archive on all three runners. Between the Namespace jobs, only env -u LC_ALL changed. Debug logging was off for this timing run. The cache-reuse regression check rejects the unchanged result (3/59) and accepts the fixed result (59/59).
This is one bounded contributor job, not pandas’ full CI matrix: revision 717bcd3, its locked Pixi Python 3.12 environment, an editable Meson build, two compiler processes, and two pytest workers. A small Python helper rename was applied identically. Every job had a fresh runner, checkout, environment prefix, and build directory.
